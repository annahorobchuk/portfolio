Three rounds of refinement

Every change was logged in the Figma file as a design change log — token, before, after, and the reason. The theme that shipped is the sum of these decisions.

Round 1 / UI Backgrounds

Neutral blacks were replaced with the platform graphite ramp.

darkElement#262626→#2A3036prompt input bg
darkPanel#141414→#181D21user message bg

Round 2 / Fine-Tuning

The primary returned to brand purple; pink was iterated into turquoise and renamed.

darkCyan#30AAB2→#909BF5restore purple primary
darkPink (iterated)#E98AD6→#61BFC5syntax-string: 4 iterations → final #61BFC5
RENAMEDdarkPink→darkTurquoise
lightPink#D547B8→#00949F
RENAMEDlightPink→lightTurquoise

Round 3 / Syntax Saturation Reduction

Code colors were dialed back so syntax reads calmly against the purple and turquoise primaries.

darkSyntaxYellow#E5D74C→#CEB31CsyntaxNumber — less vivid
NEWdarkSyntaxOrangeMuted#EDA769syntaxType only — split from syntaxFunction
REMOVEDdarkSyntaxOrangeMutedexperiment reverted the same round
darkSyntaxOrange#E98C3B (or-50)→#EDA769 (or-40)syntaxType reassigned back to darkSyntaxOrange
Teal header text — increased lightness 15% specifically for table headers and H2/H3 headings to clear contrast more comfortably
Table highlight colors — slightly desaturated orange so turquoise and purple carry more weight as primary roles (the two most visually aggressive: orange and green)
system

Not invented — aligned

No color in this theme is arbitrary. In Figma, every token is a variable aliased into the DataRobot design system library — the CLI inherits the platform's graphite, purple and supportive ramps, so it looks native next to the product. Two modes are driven by the same variable collection.
